kagent vs Azure SRE Agent

Cost and capability, for the purposes of this project's PoC (Kubernetes-native agent, minikube, DeepSeek backend).

kagent

Open source · self-hosted · Apache 2.0
$0 / month license
+ your compute + your LLM API bill
  • Runs on any Kubernetes cluster you already have (minikube, EKS, AKS, GKE, bare metal)
  • You pick the model provider — OpenAI, Anthropic, Gemini, Bedrock, Ollama, or any OpenAI-compatible endpoint (e.g. DeepSeek)
  • Agents, tools, and model config are Kubernetes CRDs — GitOps-friendly, `kubectl`-native
  • 124 built-in MCP tools: kubectl, Helm, Istio, Argo Rollouts, Prometheus, Grafana, Cilium
  • No vendor lock-in to a cloud; scope is whatever your cluster can reach

Azure SRE Agent

Managed SaaS · Microsoft Azure
~$288–292 / agent / month
baseline always-on only, before any actual work (see below)
  • Fully managed — no cluster or infrastructure to run yourself
  • Deep native integration with Azure Monitor, runbooks, incident tooling
  • Model choice limited to Azure-hosted providers (Anthropic, OpenAI, others per docs)
  • MCP server connectivity for ecosystem integration
  • Scope is Azure-hosted applications and infrastructure

Bottom Line for This Project

Why kagent fit the PoC objective

The OKR was explicit: "public open-source libraries only," local "minikube" environment, $0 licensing. Azure SRE Agent's baseline alone (~$288/agent/month, before any actual investigation work) would cost more per month than this entire PoC's DeepSeek API usage is likely to reach in a year of light use — and it only targets Azure-hosted workloads, which this project (a local minikube cluster) is not.

kagent's trade-off is real, though: you own the setup (as this project's own thinking log documents — a pre-existing Zarf webhook and a Helm CLI quoting bug both had to be debugged by hand). Azure SRE Agent buys away that operational burden at a fixed, metered price, with deeper out-of-the-box incident tooling if your workloads already live in Azure.
